# Spec Delta

## Purpose

为图片和小说收藏提供一致、可观察且可恢复的归档同步行为。该能力区分更新检查失败、收藏未变化、作品不可访问和实际下载失败，避免漏抓、重复请求及误导性汇总日志。

## ADDED Requirements

### Requirement: 收藏更新检查必须区分状态
系统 MUST 将收藏更新检查结果区分为已变化、未变化和检查失败；任一公开或私密收藏请求失败时，系统 MUST 将本轮标记为检查失败，不得按未变化跳过详情抓取。

#### Scenario: 私密收藏请求失败
- **WHEN** 公开收藏检查成功且未发现新作品，但私密收藏请求失败
- **THEN** 本轮结果为检查失败，最终汇总包含失败信息，且不能输出“收藏未变化”作为唯一结论

#### Scenario: 收藏确实未变化
- **WHEN** 公开和启用的私密收藏检查均成功，且检查范围内的作品均已有归档记录
- **THEN** 系统跳过详情抓取，并输出收藏未变化的汇总

### Requirement: 已确认删除的小说必须幂等处理
系统 MUST 对详情接口明确返回 404 的小说记录不可访问状态，用统一的删除提示结束本次处理，不进行同一请求内的重试；后续轮询 MUST 不因该作品重复触发详情请求，并 MUST 保留已有数据库记录和本地 EPUB。

#### Scenario: 新收藏小说返回 404
- **WHEN** 收藏列表包含尚无归档记录且详情接口返回 404 的小说
- **THEN** 系统记录该小说的不可访问状态，输出“该作品已被删除, 或作品ID不存在。”，计入 404 跳过统计，且本次不重试详情请求

#### Scenario: 已归档小说之后返回 404
- **WHEN** 已有数据库记录或 EPUB 的小说之后返回 404
- **THEN** 系统保留原数据库记录和本地文件，记录不可访问状态，并在后续轮询中跳过重复详情请求

### Requirement: 一致性检查失败必须进入轮次结果
系统 MUST 将一致性检查的数据库查询失败、EPUB 校验失败、修复失败和修复时确认的 404 分别计入可识别的轮次统计；检查查询失败不得被当作“无记录”而静默继续。

#### Scenario: 一致性查询失败
- **WHEN** 最近小说记录查询发生数据库异常
- **THEN** 系统将本轮标记为不完整，输出一致性检查失败日志，并在最终汇总中体现失败

#### Scenario: 损坏 EPUB 修复时作品已删除
- **WHEN** EPUB 校验失败且重新获取详情返回 404
- **THEN** 系统输出统一的删除提示，将该项计入 404 跳过或不可访问统计，而不是输出普通网络失败

### Requirement: 跳过和失败日志必须可汇总
系统 MUST 为已有记录跳过、已存在文件跳过、404 跳过、分页失败、详情失败和轮次成功分别使用稳定的事件标识，并在轮次结束时输出成功、跳过、失败、分页失败和 404 数量；普通成功项不得伪装成重新下载。

#### Scenario: 检测到已有归档记录
- **WHEN** 收藏列表中的作品已存在数据库归档
- **THEN** 系统跳过详情和文件生成，记录带稳定标识的跳过事件，并在轮次汇总中增加跳过数量

#### Scenario: 分页请求失败
- **WHEN** 某个公开或私密收藏分页请求失败
- **THEN** 系统记录对应收藏类型和 offset，增加分页失败数量，并将轮次标记为不完整

### Requirement: 轮询异常不得终止后续轮次
系统 MUST 在单轮发生可捕获异常时输出带上下文的错误并结束当前轮，调度器 MUST 保留休眠和下一轮轮询能力；网络重试日志 MUST 标明错误分类和尝试次数。

#### Scenario: 单轮数据库异常
- **WHEN** 数据库初始化或写入在本轮抛出异常
- **THEN** 系统记录本轮异常、输出不完整汇总，并在休眠后继续下一轮

#### Scenario: 永久 404 错误
- **WHEN** 详情接口返回明确的 404
- **THEN** 系统直接进入不可访问处理，不输出后续重试日志
