# Proposal

## Why

小说收藏已经支持 EPUB 归档，但它与图片收藏在更新失败、404、完整性检查和日志汇总上的行为仍不一致。部分异常会被当成“收藏未变化”，导致私密收藏漏抓；已删除小说也可能在每轮重复请求，降低轮询可靠性并增加无效日志。

本次变更把两类收藏流程的可观察行为统一到明确的成功、跳过和失败状态，同时保留小说归档与图片下载在产物格式上的必要差异。

## What Changes

- 为小说更新检查引入明确的检查失败状态，公开或私密收藏请求失败时不得被判定为“收藏未变化”。
- 将小说 EPUB 一致性检查的查询失败、修复失败和删除作品结果纳入轮次汇总，并输出可区分的日志。
- 为已确认不存在或已删除的小说增加跨轮询的处理记录，避免每轮重复详情请求，同时保留已有数据库记录和本地 EPUB。
- 统一小说与图片流程的跳过、404、限流、分页失败和轮次汇总日志语义；已有作品跳过日志应可统计而非静默丢失。
- 保持现有更新门控、最近记录检查、EPUB 内嵌图片和图片下载并发模型的业务目标不变。

## Capabilities

### New Capabilities

- `bookmark-archive-sync`: 统一图片与小说收藏归档的更新检查、失败状态、跳过策略、不可访问作品处理和轮次日志汇总。

### Modified Capabilities

- 无。当前项目没有已登记的 OpenSpec 能力规格，本变更建立首个可持续维护的收藏归档行为规格。

## Impact

- 主要影响 `v2.0/novel.py`、`v2.0/bookmark.py`、`v2.0/scheduler.py`、`v2.0/log_record.py` 以及数据库访问层和相关测试。
- 可能新增小说不可访问状态或处理缓存字段；需要兼容已有 `novel` 表和已有本地 EPUB，不删除历史归档。
- 不改变 Pixiv API 地址、EPUB 文件格式、图片存储目录或现有配置开关的含义。
