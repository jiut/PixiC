# Proposal

## Why

图片和小说任务目前由独立进程持续轮询，日志会交错输出。用户需要默认先完成全部图片日志，再开始小说日志。现有单轮抓取方法不能可靠证明图片工作线程、回调和文件日志均已结束，需要补齐阶段边界和失败传播。

## What Changes

- **BREAKING**：默认入口改为单进程一次性批处理，依次完成图片阶段、小说阶段并退出；取消入口中的无限轮询，由外部任务计划器负责重复启动，不提供顺序模式开关。
- 增加应用内单实例锁；锁冲突的启动立即退出并返回专用退出码 `3`，不登录、不初始化阶段资源、不写批次日志。外部任务计划器仍配置为不启动重复实例。
- **BREAKING**：批处理启动前拒绝启用爬虫或 API 的冲突配置，输出配置错误；已有收藏、小说和数据库开关继续生效。
- 扩展现有单轮抓取流程为 `run_once(stop_event, deadline)`，返回统一阶段结果；明确成功、无变化、失败和协作停止，去掉误导性的“进入休眠”结束日志。
- 建立图片线程池任务、回调和日志排空屏障，完成阶段汇总及 `IMAGE_PHASE_DONE` 输出后，才导入和构造小说任务；图片关闭或无变化同样经过该边界。
- 保留控制台实时进度、跳过日志聚合和文件完整记录，增加批次与阶段上下文及日志写入失败检测，使用现有日志队列排空能力。
- 补齐更新检查、下载、数据库写入、一致性修复和初始化的失败传播；图片单项失败但完成边界成功时继续小说，无法建立完成边界、输出失败或停止时跳过小说，保留已经完成的文件和记录。远端 404/不可访问不删除历史归档，也不重试详情请求。
- 图片单项失败只影响最终批次状态，不阻止小说；只要图片线程、资源和日志完成边界建立，小说照常运行。异常崩溃、强制终止、无法排空日志或协作停止时停止批次并跳过小说。
- 采用协作停止：停止新增请求和任务，等待活动操作与工作线程安全结束并排空日志。阶段期限是协作预算，不承诺硬时限退出或强制终止后的日志完整性。
- 明确重复批次策略：无变化跳过；图片有变化时完整分页并利用已有记录跳过下载，保留最近 20 条一致性检查和小说最新 10 条更新判断。

## Capabilities

### New Capabilities

- `global-log-order`: 定义默认单批次的图片先于小说日志顺序、阶段结果、失败边界与协作停止契约。

### Modified Capabilities

无。

## Impact

- 涉及 `v2.0/scheduler.py`、`bookmark.py`、`novel.py`、`thread_pool.py`、`downer.py`、`checker.py`、`db.py`、`ptimer.py`、`login.py` 和 `log_record.py`。
- 需要阶段结果与停止事件、线程池生命周期修复、可中断等待、明确请求超时及日志错误状态；共享下载器、线程池和数据库接口需保持其他调用方兼容。
- 更新调度、线程池、日志、下载和一致性检查测试，以及 README 中的启动、退出码和 Windows 任务计划器说明。
- 默认不再使用 `BOOKMARK_CYCLE` 安排下一轮；图片有变化时不再采用旧常驻进程的每五轮全量/其余轮约 800 条截断策略，不新增跨批次计数持久化。
- 图片文件、小说 EPUB 格式、数据库表结构和本地配置值不在本次变更范围内。
