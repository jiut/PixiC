# Design

## Context

`scheduler.py` 通过两个进程分别启动图片和小说无限轮询。`Bookmark.run()` 和 `Novel.run()` 已经各执行一轮；模块中的 `while True` 用于分页，轮询与周期 sleep 位于调度器。图片末尾“进入休眠”仅是日志，方法返回也不能证明工作线程已结束。

当前自定义 `ThreadPool` 不保存线程对象，线程启动后才注册名字；`close()` 根据瞬时名字数量发送 sentinel，存在少发竞态，没有任务完成计数或可靠 `join()`。任务和回调异常被吞，满队列提交及关闭可能阻塞，`terminate()` 不能取消活动操作。

控制台 sink 同步写入并 flush，文件 sink 使用 `enqueue=True`。当前 Loguru 0.5.3 支持 `logger.complete()`，本项目没有协程 sink，可同步等待已有队列；该等待没有超时，排空也不证明 sink 写入成功。新增图片日志缓存、EOF 或序号排序不能替代线程完成和输出错误检测。

更新检查可能把错误当作无变化；下载器可能在必要下载失败后仍返回元数据；图片一致性检查缺少结果，并可能把查询错误视为空集。仅串行调用两个现有方法会掩盖这些失败，需要在阶段契约中一并处理。

## Goals / Non-Goals

**Goals:**

- 默认单进程执行一次图片阶段和一次小说阶段，全部图片输出完成后才允许小说初始化和输出。
- 保留控制台实时进度、跳过日志聚合及文件完整记录，准确标记共享模块与工作线程的阶段归属。
- 补齐任务、回调、日志屏障及抓取失败传播，给出可供任务计划器判断的摘要和退出码。
- 支持 Windows Ctrl+C 的协作停止、可中断等待与阶段预算，保留已经完成的归档。
- 外部重复启动具有明确的更新、分页和归档跳过规则。

**Non-Goals:**

- 并行下载小说并缓存日志、顺序子进程、额外日志队列、EOF 协议或序号重排。
- EPUB、图片格式、表结构调整，跨批次计数持久化，以及用户单独备份的正式脚本映射或回退。
- 硬时限退出、强制取消不可中断操作或新增 supervisor 强杀架构。
- 在本批处理中托管爬虫/API 常驻服务；冲突开关在启动前报错。

## Decisions

### 1. 默认串行单进程与唯一启动边界

协调器替换默认入口中的图片/小说多进程无限轮询，不增加可选模式或隐式旧轮询分支。它在导入登录客户端、写入批次日志或初始化阶段资源前获取应用内单实例锁；锁已被占用时只向 stderr 报告并返回 code=3。顺序如下：

```text
批次前导：读取配置并检查冲突（不写批次日志）；获取单实例锁；安装停止处理；有启用的阶段时才懒加载登录客户端并登录
设置 images 上下文，创建图片阶段专属 Downloader/DB/checker
按开关构造 Bookmark，执行现有单轮逻辑的 run_once 适配
停止提交，等待全部任务、回调和 worker 结束
关闭图片阶段专属 Downloader/DB/文件资源；若关闭产生错误，标记 barrier 失败
输出图片阶段汇总，结束控制台聚合行
logger.complete()，检查 sink 错误状态
仅 completed/disabled：输出 IMAGE_PHASE_DONE
logger.complete()，再次检查 sink 错误及停止状态
设置 novels 上下文，按开关懒导入并创建小说阶段专属 Downloader/DB/checker
执行小说单轮，清理并输出小说汇总
设置 batch 上下文，输出最终摘要
logger.complete()，检查输出错误并返回进程退出码
```

图片单项失败不阻止小说：只要 worker、阶段资源和健康日志完成并发出 `IMAGE_PHASE_DONE`，小说即可启动，最终批次状态仍记录 code=1。图片初始化失败、无法收尾、标记或日志排空失败，以及协作停止，不建立完成边界，不构造小说。停止可能在两阶段之间到达，启动小说前必须再检查。

图片关闭时不构造 Bookmark，但仍输出 disabled 汇总和排空后的边界；小说关闭时不导入、构造 Novel。两者均关闭时跳过登录并正常完成空批次。爬虫或 API 开关启用时提前返回配置错误，包括 API 开启但数据库关闭的组合。

### 2. 扩展现有单轮与统一结果

增加 `run_once(stop_event, deadline)`，扩展已有单轮的一致性检查、更新判断、分页、下载与汇总，不将分页循环当作常驻轮询删除。旧 `run()` 如被测试或其他调用方使用，可作为单轮兼容包装；保留小说已有统计信息并适配统一结果。调度 helper 同样只运行一次，更新原有验证周期 sleep 的测试。

图片和小说不共享尚未关闭的 Downloader/DB 实例：图片 worker、连接池和文件资源必须在图片汇总及完成标记前安全结束并关闭，关闭期间产生的记录仍归属 images。`IMAGE_PHASE_DONE` 之后不得再关闭或析构图片资源；小说对象及其表初始化只能在边界之后创建。若实现选择复用无状态客户端，仍须证明图片阶段没有活动 worker 或连接使用；默认设计采用阶段专属资源以降低生命周期耦合。

`PhaseResult` 包含阶段名、`status`（completed/failed/stopped）、`barrier_passed`、计数、`unchanged`、`enabled`、错误及原因。单项下载、数据库写入或修复错误属于可恢复错误：`status=completed`、`barrier_passed=true`，保留错误计数并允许小说启动，批次最终 code=1。初始化、线程/资源收尾、日志 sink、deadline 或协作停止属于致命边界错误：`status=failed/stopped`、`barrier_passed=false`，跳过小说。disabled 用 completed 加 enabled=false 表示；无变化是 completed 加 unchanged=true。错误记录携带阶段与步骤，阶段摘要由单一位置生成，避免图片方法、wrapper 和协调器重复汇总。

批次返回码固定为：0 成功/无变化/全部关闭；1 抓取、一致性修复、下载、数据库写入、日志写入或阶段期限失败；2 配置、登录或阶段初始化失败；3 已有批次持有单实例锁；130 用户协作停止。存在多个原因时保留全部错误；有初始化或配置错误取 2，其次实际阶段/输出错误取 1，锁冲突取 3，仅协作中断取 130，其余取 0。期限到期使用 failed、reason=deadline，区别于用户 stopped。

### 3. 修复共享线程池的生命周期

- 保存实际 Thread 对象，启动前注册；创建、关闭、提交和计数状态通过锁保护，避免启动注册竞态和超出并发上限。
- 尊重队列容量参数，定义 close 后拒绝提交的明确行为；提交等待可以检查 stop_event/deadline，不能永久堵在满队列。
- 任务完成计数涵盖回调，每个出队项在 finally 中完成记账。收集任务及回调异常，返回给阶段；保留已有成功/失败回调参数。
- close 幂等且尽量非阻塞，停止新提交并可靠唤醒所有 worker；不用瞬时名字数量作为全部线程凭据。关闭操作不得因满队列失去停止响应；待执行任务由显式 `join(stop_event, deadline)` 完成 drain/取消记账，旧 crawler 调用仍可只调用 close 而不改变其提交接口。
- `join()` 等待所有实际线程退出，阶段在 finally 中执行关闭及等待。任何轮询等待或 timed join 返回都不表示线程已消失；活动操作未结束时不得汇总成功、切换上下文或启动小说。
- 停止后未开始的排队任务在开始边界检查停止标志并计为取消，活动任务安全收尾，所有回调与队列记账仍完成。不能用原 `terminate()` 紧循环假装取消线程。

共享池的 crawler 等调用方保持原 `pool.put(func, args, callback)` 和 `callback(status, result)` 调用兼容性；新增的停止、deadline、异常字段通过池状态或可选扩展接口传递，不改变旧回调参数。测试覆盖快速 close、满队列、重复关闭、延迟回调、任务/回调异常、停止以及既有调用方式，不以睡眠后线程数猜测完成。

### 4. 失败从实际操作传递到阶段

图片 `check_update()` 改为 changed/unchanged/error；先校验所有启用的公开/私密响应和数据库检查，再判断前十个候选，不能遇到公开新作品就提前掩盖私密错误。空列表是有效 unchanged；数据库关闭时按既有行为进行分页。登录失效和分页失败计入错误。

`downer.py` 的详情、filter 和 Single/Multi/Gif 下载链传递必要下载的成功/失败，可用明确返回值或异常，不强制新增复杂结果类型。有效元数据不能作为下载成功的凭据；filter 按配置拒绝下载是预期 skip。数据库 insert/update 返回 False 是失败，不输出成功或把未完成文件标为成功入库；数据库关闭也必须验证文件下载完成。

`checker.run_startup_check()` 返回检查、通过、修复、失败、不可访问和跳过计数，正常通过仍仅输出汇总。`db.select_latest_records()` 为阶段提供可传播查询异常的严格路径，兼容其他调用方；查询失败不能转换为“空表”。数据库关闭表示 skipped。确认远端不可访问的归档保留并单独计数，实际修复失败令图片阶段失败。

作品详情接口确认的 404/已删除/不存在与明确不可访问不按网络瞬态错误重试、不删历史数据库记录或本地文件、不算阶段失败；数据库提前跳过已有作品仍不发详情请求。CDN 内嵌图片的 404 属于资源下载失败，可按现有有限重试策略处理，最终不可用时必须使 EPUB 生成失败，不能误归类为作品详情 404。阶段失败不回滚已完成作品，后续运行利用既有跳过规则继续处理。

去掉或调整吞掉顶层错误的 `@logger.catch`，使结果明确；初始化中的 `exit()`/`SystemExit` 应改为初始化异常，或由协调器在初始化边界规范为 code=2，即便其原始 exit code 为 0。其他未知异常进入失败结果并执行清理。

### 5. 实时输出、上下文和可检测排空

复用现有同步控制台和 enqueue 文件 sink。提供统一阶段结束输出接口：完成控制台聚合状态、显式 `logger.complete()`、读取线程安全 sink 错误状态。阶段汇总应正常清理聚合行，文件和重定向仍包含每条原始日志，不延迟图片实时输出。

日志增加 batch_id 和 phase。选择进程内受锁保护的阶段元数据，在 Loguru patch/bind 处写入每条记录；阶段只在线程全部退出后切换。这样共享 downer/db/checker 与 worker 自动获得同一阶段，不依赖不能自动跨线程传递的 contextualize。标记属于 images，最终摘要属于 batch。

控制台与文件写入包装器在每次写入异常时记录 sink、原因和批次上下文，不把 Loguru 默认 catch 或内部吞异常作为成功。异步文件 writer 记录错误后继续消费队列，让可恢复的写入失败仍允许 complete 排空；需消除受影响控制台路径中的静默吞错。文件创建/轮转异常也纳入错误状态，输出已经损坏时仅尽力向可用 stderr 报告，不递归写回故障 sink。

正常 images 汇总排空后检查错误，写入 `IMAGE_PHASE_DONE` 并再次排空、检查；只有两次检查均通过才允许小说启动。小说和批次摘要后同样排空并检查，晚到的文件写入失败必须使返回码非零。健康 sinks 才承诺日志完整；complete 内部无 timeout，文件系统永久阻塞不能承诺退出期限。

验证直接记录实际 sink 接收事件和 worker/callback 完成事件，断言最后图片记录、汇总、标记、小说初始化、小说摘要、最终摘要的先后关系。测试同步控制台、enqueue 文件输出、TTY 聚合与重定向、文件写入和轮转失败；不引入单调序号作为顺序成立的证据。

### 6. 协作停止与阶段预算

协调器维护 stop_event，Windows SIGINT/Ctrl+C handler 只设置事件，不直接调用 logger、排空或清理，避免打断持锁日志时发生重入死锁。POSIX 可另注册 SIGTERM；Windows 的 TerminateProcess、Process.terminate() 和任务计划器“结束任务”不属于可优雅捕获的停止。

deadline 使用 `time.monotonic()` 表示阶段协作预算；在新请求、分页、作品、重试和提交边界检查。预算到期停止新增工作并记录 failed/deadline；用户停止记录 stopped。请求使用明确连接/读取 timeout，但 requests 的 timeout 是连接/读取无活动超时，不是整个响应的绝对期限。

将图片 Timer 递归等待改为有上限的循环，在再次请求前检查累计等待及停止状态；恢复后返回正常结果，持续限流达到上限返回失败，不能无条件记录“恢复访问”。Downloader 自适应限速、退避和小说重试用 event.wait 或等价可中断等待。登录 `get_user_id` 等请求补齐 timeout，并在登录/初始化边界观察停止事件。

GIF 转换、数据库、磁盘、日志排空或 Selenium 操作可能不支持安全取消；停止只能等其结束。不得用 `join(timeout)`、后台残留线程或强杀跨过图片屏障。强制终止可能留下临时文件、部分写入和丢失尾部日志，不在本变更提供强杀补偿保证。

### 7. 重复批次与外部调度

保留图片最近 20 条一致性检查，以及图片/小说最新 10 条更新判断和小说最近 20 条完整性检查；通过项仅记录汇总。小说无变化时仍执行既有最近 20 条一致性检查，但不重新分页或逐项校验整个收藏列表。

原 Bookmark 每个新对象的 day_count=5，常驻进程靠内存计数每五轮全量、其他轮约 800 条截断。一次性批次明确采用“无变化跳过、有变化完整分页”，不持久化计数、不在 batch 路径执行旧轮数截断。已有数据库/文件跳过规则避免重下；公开和私密列表各自从 offset=0 开始，前一列表失败也不能把 offset 带入后一列表。允许后一列表继续处理，但保留已发生错误。

README 给出 Windows 任务计划器配置：使用绝对路径 `.venv\Scripts\python.exe` 与 `v2.0\scheduler.py`，起始目录为 `v2.0`，保持相对 Cookie 等路径正确；选择“如果任务已在运行，则不启动新实例”。该配置保证单实例批次顺序，多个外部并发启动不在本进程顺序保证内。`BOOKMARK_CYCLE` 不再控制默认入口，周期在外部设置。

## Risks / Trade-offs

- [活动操作或文件系统卡住] -> 协作期限不保证硬退出；文档说明停止限制，不能提前启动小说。
- [共享线程池/下载器修复影响其他调用方] -> 保持调用兼容，覆盖 crawler 提交方式、下载过滤和数据库关闭场景。
- [默认运行方式及分页策略变化] -> 明确 breaking 行为、外部调度配置和返回码，测试超过旧截断范围的分页。
- [sink 写入失败被吞或 writer 提前退出] -> 错误状态独立于 drainage，writer 可报告失败并继续消费，按健康 sink 验证顺序。
- [意外并行外部启动] -> 外部任务计划器配置单实例，应用内单实例锁在批次日志和登录前拒绝重复进程，锁冲突返回 code=3。

## Migration Plan

1. 先落实结果、线程池与失败传播，再接入输出屏障和默认串行协调；全部任务保持未完成直到代码及对应验证落地。
2. 在不访问真实账号的测试中覆盖配置矩阵、成功/无变化/失败/停止、延迟 worker/callback、故障 sink 和重复启动，再运行现有回归及编译检查。
3. 文档提供绝对路径启动命令、起始目录、0/1/2/3/130 退出码、阶段标记和协作停止限制。按外部计划器配置周期和禁止重复实例。
4. 保留既有配置值、数据库和已下载成果；回退使用变更前代码版本并恢复旧启动方式，无需数据库迁移。
